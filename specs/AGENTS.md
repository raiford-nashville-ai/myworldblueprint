# Specifications

## Purpose

Record product requirements, implementation plans, architectural decisions, and verification evidence.

## Rules

- Read world-spec.md and website-spec.md before changing product behavior or architecture.
- Use hugo-build-plan.md for phase boundaries and asset-architecture.md for source ownership.
- Update documentation when an authorized implementation changes the architecture.
- Label proposals and unresolved questions; do not present them as accepted requirements.
- REFERENCE_UI.html is a frozen, byte-identical copy of ../mocks/polished-sidebar.html. Change the baseline only with explicit user approval.
- Record tests actually run, their environment, failures, and coverage limits in verification notes.
- Do not rewrite ../blueprints/ to resolve a specification conflict without approval.
