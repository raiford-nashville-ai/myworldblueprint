# Blueprints

## Purpose

Preserve the world's governing architecture, canonical meaning, and reusable model-request prompts.

## Permissions

- Read these files to understand the world before designing or implementing its expressions.
- Do not create, edit, rename, or delete files in this folder without explicit user approval for the requested blueprint change.
- Approval to implement the website does not authorize changes to its blueprints.
- If implementation exposes a conflict or missing definition, report it and propose a change before writing here.

## Boundaries

- master-blueprint.md defines the foundational world grammar and invariants.
- context-knowledge.md supplies supporting conceptual context; surface conflicts rather than silently reconciling them.
- world.md is intentionally unpopulated until the user provides or approves a world blueprint.
- prompts.md contains user-request templates, not repeated system-level world definitions.
- Keep canonical facts distinct from proposals, examples, and generated expressions.
- Preserve stable identity, lineage, and relationship meaning when an approved change is made.
